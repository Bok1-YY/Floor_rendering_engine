## 一、贯穿全程的核心思维模型（先看这些「元原则」）

这些原则不是写在某一天，而是**反复在每一条日志里生效**。理解它们，就理解了这个项目所有决策的底层逻辑。

### 1. 「引擎零改」—— UI 只是引擎的一层皮
> 所有重逻辑（提示词组装、模型调用、记录持久化、识色、配方、导出）都在 headless 引擎模块里；任何 UI（老 NiceGUI / 新 Next.js）都只是「调引擎」。

这是能做[[architecture|绞杀者式迁移]]的**前提**：勘察确认「全引擎里只有 `webui.py`/`__main__.py` 依赖 nicegui，其余 ~5300 行前端无关」，于是迁移成本 ≈ 重写一个 UI 层。改业务优先落引擎模块，换 UI 时引擎原样复用。

### 2. 「保真锁死，创意放开」—— 一锁一放
地板效果图的生命线是**地板本身的物理保真**（尺寸/拼缝/光泽/色调/占比 40-50%/无缝/倒角/色锁/负面词）。所有涉及创意的改动都必须**先证明地板技术层逐字节不变**。

这个模型在 **Omakase 模式**（见下文第二节与决策对照表）里被推到极致：提示词显式拆成**场景创意层**（AI 散文接管）+ **地板技术层**（代码拥有、逐字节锁死）。DeepSeek 只产候选、绝不写最终提示词。

### 3. 「Golden 回归 + 字节比对」是保真的唯一护栏
生图质量无法自动断言（要人眼看 4K），但**提示词字符串可以**。于是：
- `tests/golden/*.txt` 锁住核心工作流的 prompt 输出（含 Omakase、无缝拼法专项、墙板模式）；
- 每次改提示词都做**改前/改后字节快照对比**，凡「应一致」的路径必须逐字节相等，「应改变」的路径人工核对 diff 后再 `UPDATE_GOLDEN=1` 刷新。

→ 详见 [[architecture]]。这条护栏在 [[bevel-saga]]、**串味** 里都是最终裁决者。

### 4. 「本机自用工具」的校准 —— 拒绝过度工程
反复出现的判断：**把通用 Web 工程规范硬套到「单用户本机自用、未来可能打包给同事」的工具上，很多并不成立**。
- `2026-06-23` 评估 14 条缺陷清单，结论「大半不成立」（全局状态是有意设计、JSON 已有按文件锁+原子写、字典外置成 JSON 反而自废 git-diff 追踪），只挑 3 项真值得做的实修。
- `2026-06-18` 评估 Codex 的「通用 Web 加固」方案，只取真有价值的（job_id 唯一化、上传路径逃逸防护），把最危险的 TLS 项改成「先可配置、实测后再翻默认」。

### 5. 「诚实标注」验证边界
每条日志都严格区分：**已自动验证的**（py_compile / import / pytest / 无头截图）vs **待用户真机人眼确认的**（4K 出图保真、浏览器端到端）。地板保真「遵 `floor-ai-fidelity-manual`，仍人工确认」是长期约定。

`2026-07-09` 的人工评审功能把这个原则产品化：系统不替人判断“好不好”，只把人的判断结构化保存为通过/备选/淘汰、问题标签、备注和最佳图，后续用于筛选、导出与复盘。

### 6. 早期「无 git，靠开关而非 revert」
项目早期无版本控制，所以危险实验一律做成 **opt-in 开关**（默认关＝生产零变化），「不行就删开关键回滚」。这直接塑造了 [[bevel-saga]] 里「四档策略选择器」的形态。后来才 `git init` 成独立仓库。

## 二、架构大改动时间线（为什么从 A 换到 B）

### 🏛 最大的一次：NiceGUI 单体 → FastAPI 无头 + Next.js 真前端
**这是整个项目的主轴。** 从 `2026-06-25` 那条「本仓库诞生」开始。

- **换掉什么（方案 A）**：`floor_engine/`——一个 NiceGUI 单体（`webui.py` ~2558 行，`main_page()` 一个函数吃 ~1740 行）。
- **为什么换（四类痛点全中）**：① 调样式跟 Quasar 打架；② 长 4K 请求卡顿/假死；③ 写交互逻辑别扭；④ 想要的效果做不出。叠加**工具定位确认为对外商业产品**。
- **换成什么（方案 B）**：真前端 Next.js + FastAPI 无头后端，前后端解耦。
- **怎么换（绞杀者模式，分 3 步）**：
  - **STEP1**：从 `floor_engine/` 1:1 fork 出 `Floor_engine_server/`，`git init` 独立仓；新增唯一源码 `server_api.py`（FastAPI 无头层），引擎零改。老版冻结、只兜底。
  - **STEP2 → 2.5**：Next.js 前端落地 → 全量参数补齐 → webui 功能全量 parity（记录/用量/导出/识色/配方/重抽/磨缝…）。
  - **视觉重设计**：照 Claude Design 的 `.dc.html` 原型整站换皮（珊瑚陶土 + 奶油米色令牌）+ 侧栏外壳，reskin 而非重写、逻辑逐字保留。
  - **STEP3**（`2026-06-29`）：退役并删除 `webui.py`（~2558 行），`requirements.txt` 去 `nicegui`，整包纯 headless。日常兜底改由冻结原型 `floor_engine/` 承担。

> 心智要点：**「不 push cutover」**（`dont-rush-cutover`）——STEP3 曾被无限期延后，直到 `web/` 完全 parity、`一键启动.bat` 根本不经过 webui、webui 在生产链路上已是死代码，才在用户确认后退役。

### ⚙ 长请求根治：同步阻塞 → 异步作业队列 + SSE
- **病根**：出 4K 图很慢，长 HTTP 连接会被**公司软路由（透明代理）reset**（记忆 `floor-ai-network-env`）。
- **老方案**：HTTP 为整个 4K 生成挂起 → 必然被 reset。
- **新方案**：`POST /api/jobs` **秒回 `job_id`** → 生图在后台 `asyncio` task 跑 → `GET /api/jobs/{id}/stream`（SSE）每秒推进度。触发请求立刻返回，根治 reset。

### 🔀 并发模型的三次演进（效率 vs 稳定的拉锯）
1. **全局信号量**（`max_concurrent_jobs`，默认 5）→ 最坏 5 任务 × 2 模型 = **10 个并发 4K 请求**，正是被软路由重置的根源。
2. **每模型信号量各 1**（`2026-06-23`）→ 双模型任务串行（一次只跑 2 张）。用户长期经验：「一次只生成 2 张图最稳」。
3. **模型级流水线**（`2026-06-24`）→ B2/Pro 各自占槽、跑完即放，下一队列任务的**同名模型立刻起跑**。解决「B2 已出图、Pro 还在跑时下个任务起不来」。并发上限不变，只是两张槽可来自不同任务。
   - 配套：卡片徽章从 job 级单句改为**分模型**（`B2 ✓ · Pro 生成中`）。

### 🧠 智能配方：手攒通用 → 按地板色调 + 联网佐证
- **老方案**：5 条手攒通用配方。
- **新方案**（`2026-06-23`）：复用 `FLOOR_TONE_STYLE_RECOMMEND_MAP`，`recommend_recipes(tone)` 按识别色调出方案；新增 27 个**国际/中性风格**的「拍摄·工艺画像」（取自联网搜索佐证：浅暖橡→北欧/海岸；深胡桃→暗奢/中古…）。**故意不给东亚/国内样板感风格建画像** → 配方默认国际中性（仍可手选）。
- 关键约束：配方**不覆写色调**（始终用识别值），也**不再覆写板材尺寸/拼缝/光泽**（那是跟着小样定的物理属性，只填「风格与画面」区）。

### ✍️ Omakase 模式：子特性 → 独立工作流
- **第一版**做成「纯效果图表单里的可选区块」→ **用户纠正**：要的是与 纯效果图/替换/宠物/参照 **平级的工作流**。后续又新增墙板模式，Omakase 不再是最后一个工作流。
- **改造**：选中后隐藏所有非必填选项，只留必填（地板图/规格/输出/模型 + Omakase 诉求）。后端管道（scene_override 贯通 + DeepSeek 客户端）全复用，只改「入口形态」。同时把上一版塞进纯效果图 else 的 `scene_override` **还原**为原始纯枚举——纯效果图不再消费它，逻辑更干净。

### 🖼 Nano Banana 2 Lite：想当平级 4K 模型 → 定位为「快速预览」
- **调研结论**：Lite **只出 1K、不支持 2K/4K**，撞「4K 是硬需求」红线，**不能**当 B2/Pro 平级模型（那要改 ~32-40 处且产出不达标）。
- **改定位**：出 4K 大图前的**快速预览/草稿**，做成独立后台任务 + 前端短轮询，**零改动** 4K 主编排。关键手法：给 `save_task_files_html` 加 `persist=True` 开关，`persist=False` 时借用完整提示词逻辑但不新建 JSON 记录。

## 三、重大 Bug 与调试历程（招牌战役）

### 🥇 圆弧倒角「双峰失败」—— 贯穿一周的判断力试炼
项目**最深的一次调试**，值得单独一篇：见 [[bevel-saga]]。
一句话梗概：多轮实验（照图开关 → UI 开关 → 四档策略选择器）后**全部撤回**，回到 `2026-06-23` 基线。真正的收获是一条**诚实的认知**——「薄高频缝在生图模型里本就有随机性，提示词移动分布、未必消灭坏抽卡 → 仍要配合多抽一批挑好的」。这是「**承认无法用工程手段消灭随机性**」原则的最佳注脚。

### 🌍 Gemini 地区封锁（geo-block）
- **现象**：生产日志连续 `HTTP 400: User location is not supported`，B2/Pro 同时失败。
- **根因**：请求已到达 Google 被干净回绝（规整 JSON、非代理重置、非 Key 问题）——出口线路的境外落地节点掉了，4K 请求从大陆 IP 出去被按地区拦下。
- **修法**：`failure_kb` 加 `geo_block` 规则（此前落到「未知错误」误导成疑难杂症）；并**破例**把这条 400 纳入「自动转 Fal」——原逻辑「400 一律不转线」，但这条 400 本质是线路落地问题，Fal 不走这套封锁。

### 🔌 在线翻译 SSL 崩溃 → 换后端 + 强制走代理
- **现象**：日志频繁 `SSLError(...UNEXPECTED_EOF...)`，打的是 `api.mymemory.translated.net`。
- **三叠加根因**：① MyMemory 是国外端点、被软路由 reset；② 它由 deep-translator 自己发请求、**完全不吃我们给生图配好的代理/TLS**；③ 免费额度有限、重试仅 2 次。
- **修法**：`MyMemoryTranslator` → `GoogleTranslator` 并**强制走本地代理**（与生图侧同一个 `proxy` 值）。附带修一个真 bug：翻译彻底失败的兜底从 `[金毛犬]` 改为裸 `金毛犬`——带方括号的中文进 Gemini 被当格式噪音，**比裸 CJK 更糟**，是唯一直接打到出图质量的翻译 bug。

### 👁 参照模式「从没把参照图喂给模型」
- **现象**：参照模式「很怪、出图很多没法用」。
- **根因（大坑）**：参照模式**从不把参照图喂给生图模型**——先用视觉模型把照片转成 9 个文字字段，再把文字塞进 prompt，生图模型只拿到「地板小样 + 文字」，**从没"看见"过参照图**。而 `call_gemini/fal_generate` 本就支持 `style_ref_image_path`，通道现成却没用。
- **修法**：参照图直接当 sref 喂模型（图+文混合，文字降级为辅助）；语境可选（跟随全局市场开关）；收紧地板可见度到 40-50%。

### 🧊 终态任务卡「点操作后前端冻结」—— 前后端契约错位
- **现象**：已完成/失败的卡点 重试/重抽/磨缝/二改 后卡片冻结，后台图跑完也不刷新。
- **根因（精妙）**：这四个端点都是「先 `create_task` 排后台、再**同步** `return _job_view(job)`」，二者间无 `await` → 回执里 `status` 仍是**终态**。前端 `JobCard` 用 `status∈{queued,running}` 决定是否开 SSE → 拿到终态快照 → 不订阅 SSE；而轮询的 `setJobs` 又进不了已挂载卡的 `useState`。**死锁**：状态不变 → 不开 SSE → 状态永不更新。
- **修法**：四端点在 `create_task` 前**同步预置**与后台 task 一致的状态转移，让 `_job_view` 立即回报 active、前端即刻开 SSE。

### 💾 配置文件「静默清零」数据安全 bug
- `config.py` `_save_config` 原**直接覆盖写** → 中途截断 = 三把 key 全丢、且被下次保存二次覆盖。改 **tmp + `os.replace` 原子写** + PermissionError 短重试；损坏时改名 `.corrupt_<ts>` 备份而非静默清零。`records.py` 写侧同加重试（Windows 撞无锁读者会 PermissionError → 已计费成图却丢记录条目）。

### 🕳 测试的「假保护」—— 零覆盖的绿灯
- **发现**（`2026-07-02`）：`tests/` 全部 `from floor_engine.*`——**测的是旧同级包，对本仓库零覆盖**。历次「pytest N passed」是**假保护**。
- **修法**：重指向 `Floor_engine_server.*`，重指后基线 33 passed（证实两包在 golden 路径逐字节等价），再补 golden（omakase/seamless_square/seamless_hb）+ 语义锁，现 38 passed。

### 🔺 无缝正方形拼的 chevron 串味
- `SEAMLESS_NEGATIVE` 硬编码 "printed chevron grain motif"，正方形拼分支没定义 Pro 措辞 → 「无缝+正方形拼」被以最高优先级命令渲染**人字纹**，与正文方格描述打架。修法：motif 抽成按拼法变量 `SEAMLESS_NEGATIVE_MOTIF`（人字=chevron / 直拼=直纹 / 方格=微色差方格）。字节比对护航。

### 🗂 生成页配置切页丢失 → localStorage 草稿
- **根因**：App Router 下 `/`↔`/records` 是别路由、`next/link` 迁移 → `GeneratePage` 每次**重挂载**，而配置全在组件内 `useState`、无持久化 → 迁移即清零。
- **修法**：新增 `draft.ts`（版本化 key、SSR/损坏双兜底），恢复逻辑**合并进 `getOptions().then` 异步回调**而非单开 effect——为避开 React19/Next16 新 lint `set-state-in-effect`，同时保持 SSR 安全、成为单一恢复点。

### 🧮 内存优化三连
用户反馈「非常消耗内存」，定位三账户并逐一低风险修：① 结果图走**缩略图**（`im.draft` 解码即降采样，浏览器不再解 4K 位图）；② 磨缝校色 `_match_color_to_reference` 峰值 ~576MB→~292MB（uint8 统计 + 原地变换，**逐像素 diff=0** 保真零损失）；③ 卡片/候选**自动收口**（只删最旧的终态，running 永不删）。

## 四、决策对照速查表（方案 A → 方案 B）

| 领域 | 方案 A（旧） | 方案 B（新） | 触发原因 |
|---|---|---|---|
| UI 框架 | NiceGUI 单体 `webui.py` | FastAPI 无头 + Next.js | Quasar 难调/4K 假死/交互别扭 + 商业化 |
| 长请求 | 同步 HTTP 挂起 | 异步作业队列 + SSE | 软路由 reset 长连接 |
| 并发 | 全局信号量(5) | 每模型信号量(1) → 模型级流水线 | 10 并发被 reset → 效率与稳定平衡 |
| 智能配方 | 5 条手攒通用 | 按色调 + 联网佐证的中性画像 | 出图「像国内样板间」 |
| 翻译后端 | MyMemory（不吃代理） | GoogleTranslator（强制走代理） | SSL 崩溃 + 兜底方括号污染 |
| 翻译兜底 | `[原文]` | 裸原文 | 方括号进 Gemini 当噪音 |
| 参照模式 | 只喂文字字段 | 图+文混合喂 sref | 模型从没看见参照图 |
| Omakase | 纯效果图子特性 | 独立第五工作流 | 用户要平级模式 |
| Lite 模型 | 想当平级 4K | 快速预览通道 | Lite 只有 1K |
| 圆弧倒角 | 多档策略实验 | 撤回 + 多抽挑好 | 实测都不如基线（[[bevel-saga]]）|
| 测试导入 | `floor_engine.*`（旧包） | `Floor_engine_server.*` | 零覆盖假保护 |
