# 两居室 DWG 渐进测试集

生成日期：2026-08-14

这个目录包含 10 份从公开网页取得的真实 DWG，全部是两居室；没有用三居室凑数。原始 DWG 内容未被清洗、重画或修改，只做了文件重命名。每份图的 PNG 预览位于 `previews/`，完整机器可读信息位于 `manifest.json`。

## 先说清楚“毛坯”范围

公开的住宅 DWG 很少是真正只含墙、门、窗的交付文件，大多至少含洁具、床位或厨房符号。本测试集采用“毛坯优先、单户优先、家具干扰尽量少”的筛选口径，并剔除了以下候选：

- 多户重复拼版或整栋公寓标准层；
- 五居室误标为两居室的文件；
- 只有立面被程序选中、没有可用平面的文件；
- 1.5 万到 4.4 万个爆炸实体的超复杂设计图；
- 下载不完整、不能由本地 DWG 转换器读取的文件；
- 大量家具、景观、车辆或施工详图占主导的候选。

因此，这 10 份不是“零家具合成图”，而是从相对简单、图层较清楚的单户平面开始，逐步加入普通图层、英制单位、内院、块引用和多图框。这样既能先验证成功路径，也能逐级暴露真实解析问题。

## 文件有效性验证

- DWG 数量：10；预览数量：10。
- 10/10 文件拥有合法的 AutoCAD DWG 版本签名（AC1015、AC1018、AC1027 或 AC1032）。
- 10/10 文件已用项目内 `FloorEngine.ACadSharpDwgConverter` 3.6.35.0 真正转换为 DXF；转换失败数为 0。
- 每份文件均计算了 SHA-256；见 `manifest.json`。
- 单位默认由 DWG 转换后的 `$INSUNITS` 读取：1=英寸、2=英尺、4=毫米、6=米。若头字段与图内显式房间尺寸或总面积唯一冲突，只允许在 mm/cm/in/ft/m 的有限集合内做可审计纠正；不使用门宽或“房子通常多大”的先验猜测。03/04/06 已走这条证据链，07 因没有足够显式标注继续保持阻断。

## 建议的回归流程

1. 先上传 01，完成建模后对照 `previews/01_2br_zas_rectangular_option1.png`，核对外轮廓、每道隔墙、门洞和窗洞。
2. 再上传 02，确认成功不是针对单一户型的特例。
3. 依次处理 03 和 04 的闭合拓扑问题；每修一次都重跑 01、02，防止成功基线退化。
4. 处理 05 的“普通图层但几何清晰”识别；不能直接把所有普通线降级成墙，仍需排除尺寸线和家具线。
5. 优先修复 06 的未捕获异常，使其至少 fail-closed 并产生可查看的审计记录，再提升到建模成功。
6. 最后挑战 07–10 的内院、3DFACE、块引用和多图框。平面候选必须由几何和拓扑选择，不能依赖某个网站的图层名。
