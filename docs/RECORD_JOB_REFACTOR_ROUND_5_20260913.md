# 第五轮：记录库与任务卡重构

日期：2026-09-13。范围：记录库、任务卡、直接依赖的读取客户端和 SSE 生命周期。保持后端路由、历史 JSON、生成参数复用协议及付费恢复规则。

## 记录库

- `RecordLibraryPage` 保留默认导出，仅组装 `useRecordLibrary` 与展示层。
- `useRecordQuery` 分开管理文件目录和当前文件读取的版本及 AbortController。首次加载、切换、刷新、操作完成和本地结果恢复事件共用入口。切换清空旧内容；同文件刷新失败保留内容。目录确认当前文件消失后才选择首个可用文件，空目录进入空状态。
- `useRecordActions` 在发起时捕获文件、记录、结果身份。旧操作完成不重新选择旧文件，只按当前目标刷新内容并更新目录。按结果加同步锁，整条记录删除与子结果操作互斥；不会自动重试。共享文件删除提示与参数复用保持原行为。
- `useRecordDialogs` 按文件路径、记录 ID、结果 ID、编辑类型保存评审和二改草稿，仅限当前页面会话。切换文件关闭弹窗，重新打开对应目标恢复其草稿；失败保留输入；保存期间的新编辑不被回执清空。成功且无新编辑后清除草稿，后续切换不会再次缓存已完成草稿。
- 校色、修补和纹理投影弹窗持有打开时的文件路径，完成后刷新捕获的目标。解密密码与解密文本在关闭/切换时清除，不进入草稿缓存。
- 搜索、筛选、房间计数、结果过滤和对比规则集中为纯函数。目录、筛选栏、记录组、结果项、图片工具及编辑弹窗独立展示；评审选项和样式常量共用。保留历史全景只读行为。

## 任务卡

- `JobCard` 保留 `initial`、`onRemove` 接口；内部会话按 job_id 建立身份，变化时重建。
- `useJobSnapshot` / `JobSnapshot` 统一 SSE、父级刷新和操作回执。拒绝其他任务及较旧时间戳，按有效状态转换通知；重复完成快照不重复通知。旧数据缺少时间戳时沿用兼容行为，但不降低已知时间戳门槛。
- `useJobStream` 清理时同时使事件处理器失效，迟到 done 事件不能再更新卡片。
- `useJobCandidates` / `CandidateCache` 拥有模型选择、浏览覆盖、候选缓存、翻页意图与请求版本。每张卡片所有候选读取共用最多 4 个在途请求；相同请求合并，成功项缓存，新增候选只补缺失项，切回模型复用已有结果。单项失败保留成功项，重新进入相应模型时补取失败项。清理和显式失效中断读取并拒绝旧回执。
- 候选数变化继续重置浏览覆盖；数量减少、主动操作成功或编辑器生成新结果时按需失效缓存。快速翻页使用最新目标索引，迟到响应不能跳回旧图。移除了始终由 false 禁用的旧候选展示分支。
- `useJobReview` 在卡片内合并记录读取，结果评审缓存使用完整目标身份。候选 URL 先匹配所属记录内的规范化路径，再兼容唯一文件名；多处同名时拒绝修改，避免选错结果。评审保留已有标签与备注，切换候选不会错用原候选 ID。
- `useJobActions` 通过同步锁串行处理互斥动作，取消有独立通道。保留已有超分请求恢复、重复计费确认和本地补写恢复；不会自动重试付费调用。二改失败保留弹窗，迟到成功不清空新输入。
- 展示分为状态、当前候选、操作栏、图片工具、对比与二改弹窗。原死分支中的不确定结果说明移到实际操作栏，重复计费确认仍在动作模块执行。

## 公共接口和兼容

- `listRecords`、`loadRecord`、`jobResult` 仅增加可选 AbortSignal，旧调用仍可用。
- 公共结果身份、评审请求构建与结果操作锁位于 `lib/results/`，没有全局缓存或新的状态管理依赖。
- 没有后端路由、历史数据或 localStorage 格式迁移；没有服务端分页、列表虚拟化或安装包制作。
- 草稿和缓存只属于当前页面/卡片会话，不保证刷新后的未提交输入恢复或多个客户端之间的即时一致性。
