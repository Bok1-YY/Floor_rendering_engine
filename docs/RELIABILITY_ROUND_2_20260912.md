日期：2026-09-12。继承第一轮的单进程本机部署、历史 JSON 和现有功能。

## 问题与处理结果

| 原问题 | 本轮处理 | 验证证据 |
|---|---|---|
| SD/超分业务层将带风险的错误转换成普通字符串，丢失计费信息 | `billing_phases` 按 SD、超分分别保存 failure_code、retry_safety、may_have_been_billed、attempts 和请求身份 | 先在原实现复现风险字段为 safe；修复后保留 ambiguous 和 uncertain 统计 |
| 超分接口没有区分恢复旧请求与重新提交 | 有有效句柄仅恢复；无句柄且结果不确定须明确确认；可选请求体兼容原客户端 | 后端确认门测试、浏览器取消/接受确认测试 |
| 恢复请求可能重复计数 | 用请求身份对账，同一请求 uncertain 可变为 success，重复状态不重复累计；原累计统计保留 | uncertain→success、重复回报、旧累计数据测试 |
| 原图丢失导致无法恢复已有 provider 请求 | 恢复句柄路径不重新读取/编码原图，不重新创建 payload；超分已有句柄可以不依赖基础图文件 | 无原图恢复测试、查询失败时零生成 POST 测试 |
| 投影、修补应用的检查与保存之间可启动其他任务 | 在计算/读候选前原子登记目标操作；占用跨越记录与任务持久化；异常释放占用 | 真实端点编排测试、删除及重复编辑拒绝测试 |
| 图片保存后记录写入失败仍返回成功 | 共享本地提交服务，检查记录返回值；失败明确返回可恢复的 503，保留 PNG | 写记录返回 None 的故障注入测试 |
| 恢复本地保存可能重复追加记录或候选 | 每个操作使用稳定 commit_id、确定性结果路径和持久化日志；记录按 commit_id 去重，任务按路径去重 | 记录成功但队列失败、连续两次恢复测试 |
| 首次操作登记落盘失败可能遗留临时活动标记 | 回滚新增临时属性；图像提交初始化失败也释放占用 | 两个活动状态回归测试 |
| 保存失败后刷新页面找不到恢复入口 | 待提交列表与全局恢复条；任务卡和编辑弹窗均提供本地恢复 | 浏览器刷新后恢复测试，确认只调用本地提交接口 |

## 数据流与实现

SD 生成、超分和超分重试在调用 provider 前建立可持久化请求身份。已有有效 Fal 句柄时复用身份并查询原请求；明确允许新提交时才建立新身份。提交前的状态持久化失败阻止网络调用，且不会凭空增加不确定费用。取得 provider 结果后的状态保存失败会记日志，仍继续保存已生成图片。

`usage_stats.json` 保留 version 2 和原 counts，增量增加 `request_outcomes`。它记录请求的统计归属与最新结果，避免同一请求从 uncertain 恢复为 success 时算成两次。没有请求 ID 的原调用维持原计数行为；不推断或修正旧累计账单。

本地提交顺序：登记操作 → 保存提交日志 → 原子保存 PNG → 按 commit_id 写记录 → 更新任务候选并持久化 → 保存完成回执 → 释放临时占用。

- 日志位于输出目录 `.result_commits/<commit_id>.json`；结果位于 `result_<commit_id>.png`。
- 本轮接入真实纹理投影、修补候选应用、手动校色、SD 交付及超分交付。生成模型和图像处理算法不在恢复路径中执行。
- PNG 保存失败不会声称图片已经保留；图片保存成功、后续步骤失败时返回 failure_stage 和恢复 ID。
- 待完成日志引用图片，现有孤儿扫描会保留这些文件；完成回执不再阻止用户日后删除图片。
- 记录追加幂等；最终提交期间以“日志锁 → 记录锁 → 短任务状态锁段”的顺序串行处理，不持资源生命周期锁，不在锁内调用网络。
- 修补应用失败后保留原临时候选，并把会话恢复成可操作状态；再次应用同一选择承接已有本地提交。
- 记录被删除、源结果不再有效、任务卡被移除等情况不会自动重建原记录或任务。已保存图片仍可查看；恢复须满足目标有效条件。
- 启动时挂接未完成日志，仅提供恢复入口，不自动生成、不自动提交新 provider 请求。

## API 与前端

保留既有入口，增加：

- `POST /api/jobs/{jid}/sd-upscale` 的可选请求体 `confirm_possible_duplicate_charge`。
- 模型运行视图中的 `recovery_action`（resume / retry / confirm）与 `billing_phase`。
- 任务视图中的可选 `pending_result_commit`。
- `GET /api/result-commits`：已保存但未完成写入的本地结果，不返回内部记录路径。
- `POST /api/result-commits/{commit_id}/retry`：仅恢复本地写入，幂等返回完成结果。

前端显示“恢复已有超分请求”或“重新超分（可能重复计费）”；后者必须确认。记录页、校色/修补/投影弹窗和任务卡提供本地恢复入口。全局提示条可在刷新后找回待写入图片，恢复成功通过事件刷新当前记录，无需重载整页或丢弃其他草稿。

校色蒙版留档继续写入元数据。本轮统一提交的新增结果使用无损 PNG，文件体积可能大于此前部分全图校色使用的 JPEG。

## 使用与限制

重新启动后端加载源码；静态前端已经重新构建。无需批量迁移历史记录。回退前应先完成待写入结果，或备份整个运行数据目录及用量文件；旧代码不识别本轮恢复状态和请求对账逻辑。

提交日志提供可恢复的多步写入，不是数据库事务。磁盘持续不可写时无法完成恢复；图片未成功落盘时无法凭日志重建像素。任务卡或原记录已被主动删除时，不会擅自恢复它们。完成回执和请求对账索引保留用于幂等判断，会随操作历史增长。

此轮未扩展多进程/多用户部署，也未制作 Nuitka 安装包。Windows 浏览器断连压力场景中偶见 Python Proactor 的 WinError 10054 回调日志；页面行为断言通过，该连接清理日志尚未单独修复。
