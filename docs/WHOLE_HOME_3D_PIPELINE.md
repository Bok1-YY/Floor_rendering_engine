# 整屋 3D 约束链路

## 目标

户型效果图主流程不再把每个房间当作互不相关的图片任务，也不让生图模型根据文字猜空间。系统先建立一个可以复核、编辑、版本化的完整整屋模型；相机和最终图片都从这个模型派生。

```text
DWG / DXF（推荐）
  → ACadSharp 本地读取 DWG → ASCII DXF
  → ezdxf + Shapely 审计单位、结构图层、动态块、墙线、开口和家具 INSERT
  → 多套平面显式选择；CAD handle / 尺寸 / INSERT 变换写入不可变事实哈希
  → Gemini 只在已选 CAD 彩色预览上补房间语义，不能替换 CAD 墙图
或：原始户型图 / PDF
  → Gemini 首轮提取整屋共墙、房间、固定物和尺度证据
  → 本地外墙闭环 / 封闭房间缺墙 / 图纸像素对齐检查
  → 彩色墙图叠回原图，Gemini 二次修正拓扑与坐标
  → Gemini 第三轮只审核门、窗与开放连接并绑定定稿墙 ID
  → 同户型历史无硬错误候选按图纸对齐分择优，合并最新门窗
  → 人工在原图叠加层校准、补画、移动端点和审核开口
  → 锁定 WholeHomeModel
  → Three.js 生成完整可交互灰模
  → 本地几何为每个已选房间生成安全相机候选并渲染 RGB + semantic 预览
  → 浏览器灰模 render gate 按真实像素占比淘汰少地板、墙面过多或主对象不足的构图
  → Gemini 只在 render-valid 且不可改坐标的候选中复排构图；失败时也只能从合格池回退
  → 自动固化入选机位的 RGB / linear depth / normal / visible edge / semantic
  → B2 / Pro 结构写实化
  → 本地 normal / semantic 轮廓硬门禁；通过后才调用 Gemini 结构 QA
  → 单独应用地板产品
  → 本地结构回归硬门禁；通过后才调用 Gemini 最终 QA
```

旧的 `rooms[] → spatial_plan → 单房间 view_proxy` 仍可读取和导入，但不再是 `/floorplan` 页面的主链路。

DWG 路线默认使用仓库内 `tools/acadsharp_dwg_converter`（ACadSharp 3.6.35，MIT）。若运行环境没有已构建适配器，DXF 仍可直接上传；ODA 仅作为显式配置且已确认商业授权时的可选后备。CAD 解析失败、候选歧义、单位不明、墙体语义不明或事实哈希不一致都会在读取 API Key 和生图之前 fail closed，并保留诊断记录。

## 权威数据：WholeHomeModel

`whole_home_engine.py` 负责规范化、几何检查、哈希和落盘。模型使用右手系、Y 轴向上的米制坐标：

- `walls`：共享墙段，含起终点、厚度、高度、外墙/内墙类型和来源；
- `openings`：通过 `wall_id + offset_m + width_m` 绑定墙段，门、窗和开放连接不会漂到房间多边形之外；
- `rooms`：由同一全局坐标表达的地面边界和语义；
- `fixed_objects`：只记录图纸中明确存在的固定柜体、洁具、平台等体块；
- `cameras`：自动入选或人工在 3D 灰模中保存的 XYZ、target、焦距和画幅；自动机位额外记录计划 ID、候选 ID、本地分、视觉分和理由；
- `scale`：AI 尺度证据或人工校准状态；
- `source/confidence/review_status`：区分 AI、导入、人工和人工修正。

浏览器每次保存结构草稿都会使项目版本递增。墙体、开口、房间或固定物变化会使旧机位缓冲变为 `stale`；新增另一个相机不会让已经确认的结构缓冲失效。

## 人机边界

Gemini 建模阶段只做语义与几何候选：

- 读图纸文字和标注尺寸；
- 提取一次且仅一次的共享墙图；
- 找门、窗、开放连接和固定物；
- 标出不确定项。

锁定模型以后，相机分成两层。确定性浏览器算法负责产生候选坐标并完成墙外、贴墙、固定物碰撞和视线深度筛选；Gemini 只能观察原户型与候选联系表，在已有 `candidate_id` 中复排，不能创建或修改 XYZ。人工仍可在 3D 层漫游并保存特殊机位，但它是纠偏入口，不是默认必做步骤。

### 自动机位计划与可追溯回退

每个已选房间生成最多 8 个候选。候选由房间内部网格点、固定物和门窗焦点组合而成，并按墙距、可见纵深、边缘站位、焦点价值和房间面积评分。24/28mm 是基础池；20mm 作为带罚分的延迟池同时交给浏览器测量，但只有该房不存在 render-valid 基础焦距时才可启用，禁止 18mm。相机 target 高度按房型降低到 0.62–0.75m 并写入 metrics，以增加地板视野而不丢失语义主对象。

浏览器对每个候选同步渲染 RGB 和 semantic，以固定色标直接统计全画面像素。`whole-home-render-gate-v2` 的硬门槛集中在 `web/src/lib/wholeHomeRenderGate.ts`：地板至少 8%、墙面不高于 72%，任何单一家具/洁具语义角色不得占画面 40% 以上，并按房型要求床、卫浴洁具、操作台/厨电、沙发/电视、玄关柜或洗衣机/栏板达到最低占比。地板、墙面、背景和未知颜色不参与“单一角色峰值”计算；抗锯齿容差内的颜色才归类，背景和未知颜色也不会虚构成角色。结果连同精确百分比、峰值角色、分组结论和原因写入 `candidate.metrics.render_gate`。失败候选不会上传预览、不会出现在联系表，也不会进入 Gemini、capture 或付费生图；某房间全失败时只阻断该房，其他房间继续。

窄房间先在室内候选完全无解时启用相邻空间门口机位。系统会在开口有效段靠近起点、中点、终点处分别沿墙法向检查两侧房间：三处邻接必须一致；若开口横跨厨房/玄关一类房间交点，会以 `opening_spans_room_junction` 退回人工复核，而不是只看中心点后误判。相邻空间机位必须位于稳定开口的直接相邻房间，不能沿开口切线滑进墙端外的第三房；相机到目标的视线只能穿指定开口。

如果严格室内池和合法相邻空间池都无解，系统最后尝试 `doorway_inside`：优先选择 door，在门框两侧各保留至少 8cm 后沿开口切向取中心和对称点，再向目标房内移动 0.10 / 0.18 / 0.25 / 0.32m。相机必须只落在目标房间，不得落入相邻/第三房；除所依附门墙允许近距离站位外，其他墙仍保持 0.18m 安全距离，床、衣柜等全部目标房物体仍使用完整安全区，LOS、遮挡与房型语义门禁也不降级。若仍无解才明确 blocked。该机位在生图合同中记录 `entry_opening_id`，但不会冒充“相机穿过 portal”，因此不触发只属于 `adjacent_portal` 的 C008 无门扇穿洞检查。

`bedroom ↔ kitchen` 的无门扇 `open_connection` 另有独立语义硬检查。上述规则同时覆盖 `ai` 与 `ai_edited`；同墙同类型且重叠的 AI 来源门窗会保留原记录，但低置信候选被可审计地标为重复并拒绝。人工/导入记录不会被静默改写，但几何硬错误仍阻止锁定。

Gemini 每个房间只能选择用户指定的 1–2 个现有候选，并返回视觉分、理由、优势和风险。模型漏选、超选、返回未知 ID 或调用失败时，该房间立即按本地综合分补齐，不中断整屋任务；计划记录同时保存 `ai_error` 和 `selection_source=local_fallback`。随后浏览器用入选的原始坐标重新渲染 RGB、depth、normal、edge、semantic 五通道并逐个保存，最后自动创建 B2 / Pro 任务。任何一次计划的全部候选、联系表、AI 原始结论摘要、入选相机和生成结果都追加保存，不覆盖历史计划。

### 三阶段识别与本地拓扑收口

首轮先返回完整共享墙图。墙中心线必须穿过门窗，开口只能通过 `wall_id + offset` 切墙，不能用“墙在门口断掉”表达。第二轮会把首轮结果以红色外墙、蓝色内墙、绿色开口、橙色房间和白色端点叠回原图，让 Gemini 直接修正没有压在建筑线上的墙段、短阶梯和悬空端点。本地随后检查：

- 每个外墙端点是否连接到另一个外墙段；
- 卧室、厨房、卫生间、阳台等封闭房间是否存在没有墙体覆盖的边界；
- 一条标成外墙的墙两侧是否实际都有房间，若是则自动降为内墙候选；
- 墙线与原图暗色建筑线的固定采样对齐分，评分不受门窗候选数量影响。

第三轮只做门窗专项识别，使用已经定稿的墙 ID。前两轮任一轮识别到、另一轮漏掉的开口会保留为低置信度待审候选，不会静默消失。对同一上传户型重复识别时，系统不会盲目采用最后一次随机输出，而会在无硬错误模型中沿用图纸对齐更高的历史墙图，再把最新门窗候选重新挂接。2D 编辑器用红色虚线和端点圆圈直接标出本地发现的缺墙位置；有硬错误时禁止锁定 3D。

语义归一也带房间上下文：卫生间中的 `sink`、`Bathroom Sink`、洗手盆和 `basin` 统一为 canonical `basin`。若观察事实已经存在，本地不会再补第二个 AI 台盆代理；重复代理保留审计记录但不参与建模。两个确实独立的人工/导入观察物仍全部保留，由人工处理物理冲突。

## 3D 与约束缓冲

`web/src/components/WholeHomeStudio.tsx` 用同一模型同时驱动 2D 编辑和 3D 渲染。墙洞通过确定性的墙段切分生成，不使用生图模型补洞。每个保存机位会上传：

1. RGB clay：最终生图的编辑画布；
2. Linear depth：按相机距离线性映射的灰阶深度，供模型和 QA 判断前后遮挡；
3. Normal：表面朝向；
4. Edge：用 `EdgesGeometry` 导出的干净结构边线，不含三角面内部网格。
5. Semantic：以固定角色色标表达家具和固定物身份，仅作为约束，不复制伪色。

Edge 使用一次普通深度渲染：所有可见 mesh 临时换成写深度的纯白材质，同时加入 `depthTest=true / depthWrite=false` 的黑色 `EdgesGeometry`，mesh 和边线在同一个 depth buffer 内完成遮挡。渲染结束后逐项恢复 material、renderOrder、visibility、scene 和 renderer 状态并释放临时资源，不依赖跨 render 保留深度。

缓冲图、模型结构哈希、相机和画幅共同组成 `source_hash`。正式生成前后端会重新计算；任何过期或缺图机位都会被拒绝。

## 生图提示词分工

### 第一轮：结构写实化

输入顺序固定：

1. 批准的 RGB 灰模；
2. 同机位深度；
3. 同机位法线；
4. 同机位可见边线；
5. 同机位语义角色；
6. 可选风格参考。

提示词将 RGB 定义为唯一编辑画布，将深度/法线/边线/语义定义为同机位约束缓冲，将风格图限制为装修语言；结构生图不再输入原始整屋户型图。禁止新增、删除、移动、扩大或封闭墙体和门窗。

### 第二轮：地板产品

输入为第一轮结构图、地板小样、RGB 灰模和深度图。只允许修改可见地面，墙、顶、柜、家具、地毯和室外区域不得套用地板纹理。现有自动校色可以继续作为第二轮后的非阻断后处理。

## 三层自动门禁

三层证据不能互相替代：

1. **付费前灰模 render gate**：浏览器对候选 semantic buffer 做像素构图检查，决定该机位是否有资格进入 Gemini 复排和付费生成；
2. **生图后本地图像 gate**：后端 OpenCV 比较 normal / semantic / structure 的轮廓和距离变换，失败时切换已通过第一层的备用机位或修复；
3. **Gemini adversarial QA**：只在本地 gate 通过后对墙、开口、相机、固定物、材质范围逐条做对抗式审查。

后两层给出高分不代表第一层构图适合展示地板；第一层失败也不得被 Gemini 主观评分覆盖。

## 自动 QA

每次结构候选会先固定缩放到 512×384，以 normal、semantic 与候选的大轮廓计算 `coverage@12` 和距离变换均值，并永久保存红/青对齐证据。缺缓冲或指标未达版本化阈值时直接回退修复/备用机位，不调用 Gemini QA。材质阶段也先比较已通过结构与最终候选的大轮廓；本地失败只重做一次同结构材质，不能成为可交付结果。

本地门禁通过后，Gemini QA 才同时查看房间叠图、五通道缓冲、成图和地板小样，逐条检查：

- camera alignment；
- wall / ceiling silhouette；
- opening count and placement；
- 门口机位所穿开口的 kind / width；`open_connection` 必须保持无门扇、无铰链、无门槛和无高差；
- depth order and room visibility；
- fixed-volume preservation；
- flooring scope and material fidelity。

任何墙、门窗、相机或主要深度关系失败都会设置 `hard_fail`。门口保持项是固定的 `C008` 硬检查；若模型漏答，或因遮挡无法确定，同样 fail-closed。汇总分数以显式检查项为准：全部硬检查通过时，标题分不会再与“全部通过”的证据自相矛盾。

QA 请求使用独立串行槽，避免 14 张以上整屋结果在生图结束瞬间同时压向视觉接口。连接重置、SSL EOF、写超时等临时错误会自动重试两次，并把每次耗时、状态和错误追加到 `qa_attempts`。仍然失败的结果保持 `evaluation.status=unavailable`，前端提供批量补评；补评前的评价和错误先追加进 `qa_history`，不会删除或静默覆盖。

## API

主接口由 `routes_whole_home.py` 提供：

- `POST /api/whole-home/projects`：AI 新建，或从 `import_analysis_id` 一次迁移旧标注；
- `GET /api/whole-home/projects` / `GET .../{id}`：项目历史和详情；
- `PUT /api/whole-home/projects/{id}/model`：保存版本化整屋模型；
- `POST /api/whole-home/projects/{id}/verify`：本地几何检查并锁定；
- `POST /api/whole-home/projects/{id}/camera-candidates`：生成含基础焦距与延迟 20mm 池的几何候选；
- `POST /api/whole-home/projects/{id}/camera-plans`：保存全部候选预览/联系表，执行受限 Gemini 复排并返回入选相机；
- `POST /api/whole-home/projects/{id}/captures`：保存自动或人工 3D 相机和五通道缓冲；
- `POST /api/whole-home/runs`：按机位并行提交 B2 / Pro；
- `GET /api/whole-home/runs/{id}`：轮询结构、地板和 QA 状态；
- `POST /api/whole-home/runs/{id}/qa/retry`：只补评网络失败项，串行重试并保留原 QA 与尝试历史；
- `POST /api/whole-home/runs/{id}/cancel`：停止后续模型调用。

项目和任务分别落在 `data/output_files/_whole_home/projects` 与 `runs`；缓冲图在 `_whole_home/assets`。

## 真实验证记录（2026-08-11）

使用仓库内最新真实户型和已配置 Gemini Key 完成端到端真机验证：

- Gemini 3.6 Flash：14 段墙、7 个房间、7 个门窗、2 个固定物，0 个本地硬错误；
- 浏览器：一键接受门窗、锁定模型、完整灰模漫游、24mm 机位和五通道缓冲保存均成功；
- B2 / Google 直连 / 2K：结构写实化、地板替换和 QA 共 87.1 秒；
- QA：Camera Alignment、Geometric Integrity、Opening Placement、Material Application 全部通过，`hard_fail=false`。

随后使用项目 `home_20260811_124708_007b1af4eb` 做自动主链路压力验证：本地为 7 个房间生成并永久保存 42 个候选，Gemini 受限选出 7 个机位，运行 `run_20260811_133806_c9c217000c` 同时得到 14 张 B2 / Pro 4K 终稿。视觉复核准确抓到次卧 B2 新增门洞、抬高地面和改动相机的问题；客厅 Pro 也肉眼可见把大开口封成墙。首轮 7 个 QA 请求受并发网络错误影响而不可用，由此增加了上述串行自动重试、人工批量补评和完整历史保留机制。真实点击补评后 7 项全部完成：前 6 项各一次成功，客厅 Pro 首次连接重置、第二次自动恢复，并被正确判为 `hard_fail=true`、35.5 分，证据明确包含相机改变、墙体重排和主开口消失；旧错误与 8 次尝试均留在原任务记录中。

这证明新链路已经可运行，不代表自动建模已达到施工图精度。AI 估算尺度、弧墙、异形墙、楼梯、多层、结构柱和复杂门窗仍需要人工校准；输出定位仍是营销效果图，不是 CAD、BIM 或施工交付。

Round6 使用 7 个真实主机位标定付费前灰模门禁：厨房地板 3.7%、次卧 0.16%、主卧约 0%、玄关 0.75%、卫浴 2.8% 均被阻断；次卧墙面 73.7%、卫浴 81.6% 同时触发墙面上限。客厅地板 8.85% / 墙面 47.2% / 沙发 19.8% / 电视 7.6%，阳台地板 5.45% / 墙面 68.1% / 洗衣机 11.6%，按固定合同保留。该记录是阈值来源，后续调整必须升级版本并保留旧计划中的原始 metrics，不能静默改写历史结论。
