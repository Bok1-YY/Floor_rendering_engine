# 第四轮：生成工作台重构

日期：2026-09-13。范围：生成工作台、草稿恢复、直接依赖的预览客户端与公共 Slider。沿用原有静态导出部署方式、后端路由、工作流默认值、草稿 key 和历史数据结构。

## 实施结果

`GenerationWorkspace.tsx` 保留原默认导出入口，仅调用会话组装与展示组件。`components/generation/` 按职责组织：

- `useGenerationState`：规范参数快照、默认值/历史复用/草稿恢复、场景联动、模型选择、素材及草稿持久化。复用优先于普通草稿，恢复结果一次发布；恢复前不写空草稿。选项加载期间已编辑的字段保留，其他字段正常恢复。
- `useFloorAnalysis`：当前地板的识色序号与会话有效性。更换/清空地板、离开页面使旧结果失效；用户手动修改色调后保留手动值，智能配方仍可更新。
- `rules`：共享前置校验、工作流限制、正式/自由创作请求构建、Omakase 隐藏字段处理和配方快照规则。批量也校验模型选择、SD 开关与工作流、必需素材。
- `useGenerationSubmit`：单次及两类批量提交，使用点击时的独立参数快照和同步提交锁。多地板保留逐板识色及失败回落。离开页面后尚未完成识色的条目不再启动新的生成请求。
- `useGenerationPreview`：独立拥有创建、轮询、计时器、AbortController、关闭和卸载。迟到创建 ID 补发取消；旧查询不会继续安排轮询；连续三次查询失败仍停止刷新。
- `useGenerationJobs` / `JobCollection`：统一首次/手动/定时加载，按请求版本拒绝旧列表，按 ID 合并新任务并沿用 snapshot_at 判断。新提交任务在服务端列表确认出现前保留；删除建立当前页面内的排除记录，避免旧列表复活任务卡。
- `useGenerationRecipes`：配方列表和编辑弹窗拥有独立状态。旧保存回执不能关闭新弹窗；迟到列表不覆盖本地新增、修改或已删除项。
- `useGenerationWorkspace`：组装以上模块，管理步骤展开与图片放大等展示状态；没有将旧组件整体搬到一个大 hook。
- 展示拆为产品步骤、场景/输出步骤、结果区、批量弹窗、预览弹窗和配方弹窗。展示组件通过类型限定的动作协作，网络操作由所属 hook 发起。

参数状态复用第三轮 reducer-backed store，React 与即时动作读取同一快照；请求句柄、计时器和序号由各自模块拥有。未增加状态管理依赖。

## 批量部分成功与未确认结果

成功项加入任务列表并移出批量选择；明确失败项保留供用户修正后重新提交。网络失败、服务端 5xx 等无法确认是否创建任务的情况标记为“提交结果未确认”，再次提交前要求用户核对列表并明确确认。不会自动重试创建请求。

批量执行期间锁定该批次的选择，允许关闭弹窗；后台已有提交继续完成，结束前不允许打开第二个批量会话。失败提示过长时弹窗可滚动，提交按钮仍可到达。

这些前端标记只存在于当前页面会话，不提供跨刷新/重启的严格幂等保证。后端未增加幂等键或批次协议。预览取消是尽力请求，不能保证已经开始的模型调用不计费。

## 兼容与独立修复

- 保留生成工作台默认导出、GenParams、请求字段、localStorage 的 v1 key 和旧 modelFilter 兼容；损坏草稿按字段回落，保留合法 nullable 字段。
- API 客户端仅为 previewStatus 增加可选 AbortSignal，原调用仍兼容；未修改后端路由或历史数据。
- Slider 按单值/数组值决定滑块数量，单值只渲染一个 thumb，区间保持两个。校色强度的实际键盘与像素测试增加单滑块断言，地板占比验证两端独立操作。
- 保留原正式生成/快速预览的不同模型与输出策略、配方字段规则及 UI 主布局。
