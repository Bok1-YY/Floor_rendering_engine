# 第三轮：校色与修补编辑器重构

日期：2026-09-12。范围：校色、修补及直接依赖的校色蒙版组件。保留公开组件名称、目标类型、props、后端入口、默认值和图像处理规则。

## 实施结果

本轮先在旧实现上跑通两项行为基线：校色强度调整不新增网络请求且保存参数正确；修补画笔、撤销和二值蒙版导出保持原行为。随后按职责提取实现，而不是将原组件整体转移到一个大型 hook。

### 校色

- `ColorMatchDialogImpl` 仅建立会话与组装展示层。会话身份同时包含目标、源图和参照输入；同一图片用于不同记录或任务时不复用旧状态。
- `useColorMatchState` 管理 reducer 快照；请求参数与 appliedAlgorithm/appliedIlluminationMode 分开存储。
- `useColorPreview` 拥有防抖、请求取消、版本检查、预览图片解码和错误状态。HTTP 响应与图片解码都通过版本检查后才可生效。
- `useColorCanvas` 独立拥有原图、完整预览、自动预览缓存和画布；强度调整保持本地 alpha 混合。
- `useColorMatchSession` 组织用户动作、保存和参照图替换。保存要求当前预览有效；旧会话的保存回执和上传回执不会关闭或覆盖新会话。
- 展示拆为原图区、结果区、诊断区和参数区。展示组件通过动作修改参数，不持有预览请求或直接启动网络调用；图片 URL 映射仍使用现有纯工具函数。

### 修补

- `useInpaintState` 管理编辑参数与可渲染状态。
- `useInpaintMask` 管理三层蒙版、画笔、擦除、撤销、合成和导出；添加与移除的图层及历史继续隔离。
- `useSmartSelection` 管理物件扫描、单点识别与取消；切换模式时作废旧单点请求，关闭时取消旧会话请求。
- `useInpaintTask` 管理 draw / submitting / running / pick / applying 状态与原子转换，集中处理提交、顺序轮询、候选应用、取消和清理。
- `useInpaintSession` 负责配置和功能组装；画布、工具栏、候选挑选区分别展示。
- 修补应用失败继续保留候选，第二轮的本地写入恢复入口接在应用错误路径上。恢复仅补写本地结果，不重复调用生成模型。

### 校色蒙版和共享工具

- `ColorMaskEditor` 保留原组件接口，状态与资源进入 `useColorMask`，展示进入 `ColorMaskView`。
- `session-store` 用 reducer 更新一个规范快照，React 通过 `useSyncExternalStore` 订阅。即时事件和异步图像回调读取同一份状态；少量 `.current` 访问器是快照字段的兼容访问方式，不是另存一份业务状态的 ref。
- `AsyncScope` 统一拥有当前请求、计时器、动画帧与图片回调，失效时取消资源并使旧 token 无效。图片解码在失效时完成空结果并移除回调，不留下悬挂等待。
- canvas 基础工具共用创建画布、规范化坐标与修补二值导出。校色的灰度/alpha 蒙版语义继续独立，未强行替换为修补规则。
- 未引入新的状态管理依赖。

## 修复的生命周期边界

1. 修补关闭后，迟到的状态响应不能更新 UI 或安排下一次轮询。
2. 创建任务期间关闭后，迟到的任务 ID 会补发取消，不能进入重新打开的会话。
3. 新校色参数作废旧请求和旧图片解码；旧算法响应不能覆盖新预览。
4. 旧智能点选结果不能在模式切换后修改另一模式或重新写回旧模式。
5. 会话 key 使用稳定的目标字段顺序；目标变化会重置，单纯对象属性顺序变化不会丢失编辑状态。
6. 关闭或替换参照输入时，旧上传和保存回执不再影响新会话。

## 兼容性

公开入口 `ColorMatchDialog`、`InpaintDialog`、`ColorMaskEditor` 和原目标类型继续可用。后端未增加路由，也没有数据库或 JSON 数据迁移。API 客户端的修补状态查询仅增加可选 AbortSignal；原调用方式继续有效。

保持局部校色默认、全图兼容模式、精细/经典算法与回退显示、强度及羽化默认值、修补候选数量策略和撤销上限。修补画布长边仍限制为 2048，校色蒙版仍按原 1600 限制；没有改动后端校色公式、分割模型或付费策略。
