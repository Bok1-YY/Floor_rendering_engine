# 第七轮：初始提交身份与持久化恢复

日期：2026-09-23。版本目标：7.1.2。范围为普通生成、自由创作和批量条目；重抽、编辑、修补、预览和已有计费恢复不改协议。最终测试与发布结果见[当前验证索引](./VALIDATION_CURRENT.md)。

## 问题与行为

此前两个创建入口每次都生成新任务 ID，批量的不确定状态只留在页面内存。后端已收到请求而浏览器丢失响应时，再次提交可能成为另一次生成。

现在每次明确提交在浏览器获得独立 UUID 和固定参数快照，并写入 IndexedDB。服务器在 output_files/.job_submissions 保存数据实例标识及按 UUID 前缀分目录的凭据。任务卡最多保留部分历史，凭据独立保留，不随清卡和历史淘汰删除。

同 ID、同请求返回原任务；内容变化返回 409；旧卡不存在返回 410 和原任务 ID。新 ID 代表用户主动新建一次。已受理后不再验证原文件或密钥是否仍存在，因此清掉素材不会使旧请求被误当成新请求。

## 故障边界

顺序固定为 prepared → 队列持久化 → dispatch_committed → worker 调度。凭据用临时文件、flush/fsync 和原子替换保存。请求摘要不含密钥、数据实例和提交字段；凭据本身不保存图片、完整请求体或提示词。

短受理临界区同步完成，无网络或 await，HTTP 取消不会拆断中间决定；提交锁与队列持久化锁保持既有顺序，不在任务状态锁内写盘。生成 worker 仍由统一后台管理器持有。

prepared 证明尚未调度，可以手动继续并沿用原任务 ID。dispatch_committed 消耗初始启动权；即使进程在 worker 创建前退出，重启也不推测重跑。启动修正现有队列状态，不重新造回被清掉的任务卡。文件损坏、标识不匹配、写入不确定都阻止不受保护的创建。

## 浏览器恢复

- 自动恢复只查询：进入页面、联网、焦点恢复触发；退避上限 30 秒，最多四个查询并发，隐藏页面暂停周期查询。
- “继续本次提交”先查服务器，再使用原 ID 和快照发送；当前表单修改不会覆盖原请求。
- 批量条目各有 ID，准备/提交最多四个并发；识色封存后的请求不重新识色。离开页面后未发出的条目保留待继续。
- 多标签页通过 IndexedDB 事务复用未解决的意图，最终由后端凭据去重。迟到失败不能覆盖另一标签页已确认的受理结果。
- 本地写入失败时不发送；服务已受理而本地回执更新失败时仍能从原待确认记录查回。
- 待确认记录不自动到期，隐藏不删除。已受理后删除完整快照，轻量回执保留 30 天。
- 协议旧版、数据实例变化或存储损坏显示错误，不自动退回旧创建接口。

## 接口与兼容

两个创建请求增加成对的 submission_id、submission_store_id（UUID v4）。健康接口新增 submissions.version/store_id/ready，保留 ok。JobView 增加可选 submission_id。新增 GET /api/job-submissions/{submission_id}?store_id=...；结果为 not_found、prepared、accepted、job_unavailable。路由契约总数为 102。

旧请求不带身份时每次分配内部 ID，仍可生成，但不能跨两个无身份请求去重。旧队列默认 submission_id 为空，按原逻辑恢复。数据与凭据必须一起备份；清除浏览器站点数据会丢失该浏览器的待确认列表。协议支持单进程单 worker，不保证多进程共享、手工删凭据、降级程序或不一致备份恢复后的去重。

本机制保证同一提交只获得一次初始 worker 调度权，不等于外部模型绝对只计费一次。后续重试仍使用原有计费风险确认。本轮没有付费云模型质量/账单验收或全新 Windows 机器验收。

## 验证与交付

后端定向用例覆盖并发重放、请求冲突、清卡和淘汰、各持久化阶段失败、调度失败、凭据损坏及子进程退出后恢复。前端包括协议和批量调度单元测试、浏览器存储与生命周期测试，以及真实提交 API 配离线 worker 的断响应恢复。

清除完成任务接口保留 cleared 数量，并增加 cleared_job_ids。前端对实际清除的 ID 保存本次页面会话内的删除标记，普通列表、迟到的创建确认和提交恢复响应都不能把这些卡片重新放回队列。这个标记仅约束展示；持久化提交凭据继续独立保留。新增浏览器用例在恢复查询返回前清卡，再释放旧响应验证这一边界。

全量回归、最终 exe 验证、源 SHA、附件哈希、发布与清理状态记录在当前验证索引及版本对应 JSON 中；源码测试不冒充发布包验证。发布包先验证同一 exe，再上传、下载核验与清理临时产物。
